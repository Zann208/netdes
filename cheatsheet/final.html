16. IPv4 DHCP

DHCP basics

DHCP = Dynamic Host Configuration Protocol: gives a host an IP address plus the settings it needs: subnet mask, default gateway, DNS servers, lease time, other options. Lease = permission to use an address for a limited time (IOS default with no lease line = 1 day). Server UDP 67, client UDP 68.

SettingRole
IP addressidentifies the host
Subnet maskwhich part is the network
Default gatewayway out of the subnet
DNS servername → IP lookup

Gateway and DNS solve different problems: IP to remote network works but names fail → check DNS. Lease OK but remote network fails → check gateway/routing.

Client's first broadcast stays inside its VLAN. Local DHCP server answers directly; a server across a Layer 3 boundary needs a relay on the client's gateway.

Four steps (DORA)

MsgBySrc → DstPort
Discoverclient0.0.0.0 → 255.255.255.25568→67
Offerserverserver IP → bcast/client67→68
Requestclient0.0.0.0 → 255.255.255.25568→67
ACKserverserver IP → bcast/client67→68

Offer = proposal only; several servers may offer, client picks one. Request is broadcast so the other servers know they were not chosen. Only after ACK does the client configure the address.

Slides draw all four as broadcasts; real servers may unicast Offer/ACK, and renewals are normally unicast (RFC 2131). Initial Request ≠ lease renewal.

DHCP server on a switch/router

Gateway first: VLAN needs an active SVI (interface vlan 10) or router subinterface.

ip dhcp excluded-address 10.1.10.1 10.1.10.20 ! range, both ends incl.
ip dhcp excluded-address 10.1.10.254 ! single address
ip dhcp pool VLAN10 ! any name
 network 10.1.10.0 255.255.255.0 ! subnet ID + mask
 default-router 10.1.10.1 ! VLAN gateway (SVI)
 dns-server 8.8.8.8 8.8.4.4
 lease 7 ! days; lease 0 12 = 12 h; lease infinite
 exit
show ip dhcp binding ! who got which IP
show ip dhcp pool / show ip dhcp conflict
CommandCommon mistake
excluded-addresswith d (slide typo "exclude"); excluded = never handed out, not a reservation

dns-servergetting an IP ≠ names work

Order: exclusions (global, before pool) → pool → network → default-router → dns → lease → exit → verify.

One pool per VLAN/subnet. Server picks the pool matching the subnet of the interface the request arrived on; for a relayed request it uses the relay's interface IP.

Ex: R1 G0/0.10 = 10.0.10.1/24, G0/0.20 = 10.0.20.1/24 → exclude 10.0.10.1 and 10.0.20.1, pool V10 (network 10.0.10.0, default-router 10.0.10.1), pool V20 (10.0.20.0, 10.0.20.1).

DHCP relay (ip helper-address)

Routers do not forward broadcasts. Helper on the client-facing L3 interface turns the broadcast into a unicast to the server and adds the relay IP (giaddr) so the server knows which pool.

interface vlan 10 ! client side, NOT uplink
 ip address 10.1.10.1 255.255.255.0
 ip helper-address 20.5.5.5

Server still needs: pool for 10.1.10.0/24 with default-router 10.1.10.1, and routes both ways. Helper creates no pool or route.

Only VLAN 20 gets no lease while VLAN 10 works → VLAN 20 SVI missing helper, or no pool for that subnet. Client shows 169.254.x.x (APIPA) = no DHCP reply.

IPv6 SLAAC

SLAAC = Stateless Address Autoconfiguration: host builds its own IPv6 address from the /64 prefix in a Router Advertisement (RA); no DHCPv6 lease. M flag = get address from DHCPv6; O flag = get other info (DNS) from DHCPv6. M=0, O=0 → SLAAC only (DNS via RA option).

17. Enterprise Campus Network Design

Why hierarchy

Old shared Ethernet (hub): all hosts share bandwidth, one collision domain + one broadcast domain. Switch → each port own collision domain; router/L3 switch → splits broadcast domains. Network grown without a plan → nobody can tell which path traffic takes. Good design: known traffic flows, enough capacity, room to grow, known failure plan.

LayerRoleChoose for
Accessconnect end devices; VLAN membership, filtering, traffic prioritylow cost/port, high port density, scalable uplinks, redundant paths up
Distributionaggregate access; inter-VLAN routing; security + connectivity policy (ACL, QoS); L2/L3 boundaryhigh L3 throughput, fast ports, ACLs, QoS, resilient links
Coreconnect distribution blocks; carry campus traffic fastvery high L3 throughput, redundancy, fast recovery, QoS, simple forwarding

Keep ACLs and heavy packet processing out of the core: core just forwards fast. Policy and routing belong at distribution.

ServiceResourcePath
Localsame segment/VLAN as useraccess only
Remoteother VLAN in same blockaccess → distribution
Enterprisecentral, shared by campusaccess → distr. → core

Server in another switch block is always reached through the core.

Switch block

Switch block = access switches + the distribution switches they connect to. Core joins blocks. Routing normally starts at distribution: VLANs + broadcasts stop there, so STP runs only inside each block (failure stays in one block).

Two cables to one upstream switch protect a link, not the switch. Use a pair of distribution switches; each access switch uplinks to both. Core also needs redundancy (one core switch = single point of failure).

Three switch-block designs

DesignResult
Shared VLAN (VLAN A on both access switches)trunks between all 4 switches → loops → STP blocks some links; larger L2 domain
Local VLANs (A only left, B only right)access uplinks still L2 trunks; link between distribution switches routed (L3) → no L2 loop, nothing to block
Routed access (L3 moves down)access switches route; all uplinks L3; routing protocol (OSPF) fails over; both uplinks carry traffic (equal-cost)

Sizing a block

  • Access: ports for users/devices + uplink capacity.
  • Distribution: all access traffic + inter-VLAN routing + ACL/QoS work.
  • VLAN size: reach, broadcast/multicast load, STP domain size.
  • Growth: new groups/apps and where their servers are.

~2,000 users per block = slides' historical guideline, not a protocol limit.

Block too large: distribution overloaded by routing/ACL work, or broadcast/multicast slows the block → add capacity or split the block; adding access ports makes it worse.

Core designs

DesignStructure / reason
Dual core2 multilayer core switches; distribution has redundant L3 paths into core; no single core failure point; equal-cost paths active
Multinode coreseveral core pairs joined; each block to one pair; very large campus kept modular
Collapsed coresame device pair does distribution + core; access dual-homed to the pair; smaller campus, less cost. Merges layers, keeps redundancy

Design review

  1. Mark access / distribution / core.
  2. Draw VLAN and L3 boundaries; trunk vs routed links.
  3. Each access switch → two different distribution switches.
  4. Link the distribution pair together; do not link access switches (unless stacked).
  5. Test link failure and switch failure; know what recovers (STP, HSRP, routing).
  6. Remaining link must carry all traffic after a failure.

18. Integrating Wireless LAN

Half-duplex, CSMA/CA

One channel = shared airtime, only one sender at a time (half-duplex). CSMA/CA (Collision Avoidance):

  1. Wait for idle channel + DIFS.
  2. Count down random backoff while idle.
  3. Busy → pause countdown; resume when free.
  4. Transmit at 0. Collision still possible (two counters hit 0 together).

Ex A/B/C: A sends first, B and C defer; C has shorter backoff → C next, B waits again. Avoidance reduces risk, does not remove it.

Autonomous roaming in one SSID needs the same VLAN on every AP port (end-to-end VLAN). With WLC the client VLAN only exists at the WLC.

Split-MAC (CUWN)

AP's work split between two devices. LAP (lightweight AP, cannot work alone) = real-time radio: tx/rx frames, beacons, probe responses, 802.11 encryption. WLC (separate controller for many LAPs) = authentication, security policy, association + roaming, RF channel + power, QoS. WLC also: dynamic channel/power, raise power over failed AP's area, client load balancing, RF monitoring, wireless IPS.

CAPWAP

CAPWAP = Control And Provisioning of Wireless Access Points; LAP ↔ WLC over IP (can be different subnets); replaced LWAPP.

Mutual auth with X.509 certificates. WPA2/WPA3 protects client ↔ AP; CAPWAP DTLS protects AP ↔ WLC (separate).

LAP joins a WLC

  1. Get IP from DHCP.
  2. Discover WLCs, learn addresses.
  3. Join one (fail → try next).
  4. Match image; download + reboot if needed.
  5. Secure CAPWAP; download SSIDs, VLANs, channels.

LAP loses WLC → clients dropped, LAP rediscovers (FlexConnect / backup WLC can keep clients up).

Central switching path: client → LAP → CAPWAP → WLC → campus; two clients on same AP: A → LAP → WLC → LAP → B. Troubleshoot: client VLAN/IP → tunnel/WLC → routing beyond WLC.

Roaming

Autonomous: each AP keeps own client list; old AP forwards leftover frames to new AP. WLC: controller keeps list and moves client.

Ex: Client-1 192.168.100.199 roams AP-1/WLC-1 (VLAN 100) → AP-2/WLC-2 (subnet 192.168.200.0/24): WLC-1 anchor, WLC-2 foreign, keeps .100.199. Roles belong to WLCs, not APs. Anchor stays anchor on later roams. Guest anchor: guest traffic tunneled on purpose to one WLC (DMZ).

Fast roaming + mobility groups

Joining new AP is fast; full re-login (802.1X + RADIUS + new keys) is slow. Both client + network must support:

"Remembers previous APs, up to 8" on the slide = Sticky Key Caching (SKC).

Mobility group = WLCs sharing client info for roaming. Mobility list (MAC, IP, group name) configured manually; no automatic trust; best within the same group.

19. High Availability

HA = network keeps working almost all the time even when a part fails. Campus HA: two of every device, two of every link, switch pairs joined into one logical switch (STP blocks nothing), backup supervisor that takes over fast.

Pairs still waste capacity

Each access switch uplinks to each distribution switch: survives link/distribution failure, but (1) access switches do not back each other up; (2) redundant uplinks form loops → STP blocks paid-for bandwidth.

Fix: two physical switches act as one logical switch → links to it bundle into one EtherChannel, STP sees one link.

StageResult
4 separate switchesSTP blocks uplinks; failover waits for STP
Logical access (A1+A2), separate D1, D2one channel to each D → loop through D1–D2 → STP may block a whole channel
Logical access + logical distributionone MEC; no loop; all links forward; losing a member only cuts capacity

MEC = multichassis EtherChannel: member links end on different physical switches of a logical switch.

Supervisor = brain of a chassis switch: management, routing protocols, forwarding tables. First to boot = active, other = standby (power supplies same idea).

20. First Hop Redundancy: FHRP and HSRP

Gateway = single point of failure

Host sends every off-subnet packet to one default gateway. Ex: VLAN 10 (10.1.1.0/24) hosts use R1 10.1.1.9; R1 or its LAN interface fails → nothing leaves the subnet. Adding R2 10.1.1.129 = second exit, but hosts still point at .9. Changing every host / waiting for DHCP is not failover.

FHRP: routers keep own interface IPs and share a virtual IP + virtual MAC; hosts use the VIP as gateway; one router answers, another takes over on failure.

ProtocolOriginModelBalances
HSRPCisco1 active, others standby/listenper subnet (group per VLAN)
VRRPRFC 57981 master, others backupper subnet
GLBPCiscoactive/activeper host (different vMACs)

Election (who is active)

  1. No other HSRP router → local router active.
  2. No active yet → highest priority (default 100).
  3. Tie → highest IP on the HSRP interface.
  4. Active already exists → keeps role unless a higher-priority router has preempt.

"Highest priority is always active" = false. Preempt is OFF by default; configure it on the router that should reclaim. HSRP = highest wins, STP = lowest wins.

Ex: R1 pri 110 (no P) reboots → R2 (100) active; R1 returns → R2 stays active, R1 standby. Fix: standby 1 preempt on R1.

Failover

Hello 3 s, hold 10 s. Standby stops hearing hellos → hold expires → becomes active, uses VIP + vMAC, sends gratuitous ARP (unrequested ARP reply) from the vMAC → switches update MAC tables → frames for gateway go to R2's port. Hosts change nothing (same gateway IP, same ARP entry).

21. Introduction to Quality of Service

QoS = methods to protect and prioritize time-critical/important traffic: classify, mark, limit rate, decide what to queue, send first or drop when congested. Fights delay, jitter (delay variation), packet loss. Cannot add bandwidth.

Jitter OK: VoIP <30 ms, video conf 30–50, gaming <30, streaming <100, data ~100+. VDI: mixed sizes, TCP (RDP, ICA) or UDP (PCoIP), sensitive.

Switch QoS pipeline

Classify → internal DSCP; police → over-rate dropped/marked down; mark/re-mark; choose egress queue; congestion management (which queue next) + avoidance (WRED drops early). No avoidance → full queue just drops new packets.

Trust and classification

Every packet gets an internal DSCP. Default port untrusted → DSCP 0. trust dscp keeps packet's DSCP. Trust CoS/IPP → default map ×8: 0,8,16,24,32,40,48,56.

Ex: host sends CoS 5 → trusted CoS port = 40, untrusted = 0. CoS 5 → 40, not 46 (EF): for voice trust DSCP or change map. CoS 3 → 24.

Classify by: trusted marking, port default value, ACL, NBAR (app recognition). Classify as close to the user as possible (access switch). Marking = write new DSCP/CoS/IPP (whole port or policy map; ex video server → DSCP 40).

Ex: weights 50/10/25/15 → 50/10/25/15 %. Weights 4/2/1/1 → Q1 = 4/8 = 50%, Q2 25%, Q3 = Q4 = 12.5%. Divide by the total, not 100.

Buffers split too: priority queue small (voice leaves at once), low-priority queues bigger.

Congestion avoidance

Tail drop (default): full queue drops every arriving packet → many TCP flows lose packets and slow-start together (TCP synchronization), aggressive flows hog the queue, deep queues add delay/jitter, premium dropped like best effort.

RED: random drops before full, more as queue fills; senders back off at different times; still tail drop when full; helps only TCP. WRED: thresholds/drop probability per DSCP/IPP.

Ex: 50% full → drop DSCP 0–20 randomly; 80% → also 21–31; full → tail drop. At 60%: only DSCP 18 candidates, not 26.

Best practice: voice in strict priority queue, WRR for the rest, WRED on data queues (esp. congested WAN links). AutoQoS: one command builds standard classes/policies.

Firewall

Inline between internal and external networks; every packet crosses it. Rules match: source/destination address; transport port; text in HTTP URI; TCP state (stateful = remembers sessions, allows replies of inside-started sessions).

Judged by who initiates: inside → outside allowed; outside → DMZ allowed; outside → inside denied; replies to inside sessions allowed (stateful). DMZ → inside: denied unless explicitly permitted.

DMZ = less-secured zone for servers outside users may reach (public web for www.example.com). DMZ server compromised → attacker still has to cross the firewall to inside.

IPS / IDS

IPS (Intrusion Prevention System): compares traffic with attack signatures (DoS, DDoS, virus, worm); inline; drops matching packets or redirects to another security tool; signature DB must stay updated. IDS: usually watches a copy (SPAN port) and alerts; cannot block inline.

New worm on an allowed port → port-based firewall lets it pass; IPS/NGIPS with updated signature stops it.

NGFW / NGIPS

NGFW = all traditional firewall functions + AVC (Application Visibility and Control) + advanced malware protection + URL filtering + NGIPS.

NGIPS = IPS + AVC + contextual awareness (host info to judge vulnerabilities) + reputation-based filtering (known-bad URLs/IPs) + event impact levels (rank alerts).

Products: ASA 5500-X with FirePOWER Services; Firepower 1000/2100/4100/9000; NGIPSv (VMware); Firepower Threat Defense for ISR.
