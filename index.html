Quick recap

last read

One pass through everything before the paper: the midterm topics that may come back, then the final topics. Bold lines show where a midterm idea appears inside a final question.

01 Campus model

  • Access, distribution, core. Data centres use spine-and-leaf.

02 IPv6

  • 128 bits, 8 groups of 4 hex. Drop leading zeros; :: only once.
  • FE80::/10 link-local · FD unique local · FF02::1 all nodes · FF02::2 all routers.
  • EUI-64: split the MAC, insert FFFE, flip the 7th bit: 0011.2233.4455 → 0211:22FF:FE33:4455. SLAAC uses it.

03 Switch basics

  • CAM table = MAC → port, ages out after 300 s.
  • SSH (TCP 22) instead of Telnet (TCP 23): encrypted, so confidentiality.
  • Port security: default max 1 MAC, default violation shutdown (err-disabled). Modes protect / restrict / shutdown.

04 VLANs and trunking

  • VLAN = separate broadcast domain. 802.1Q tag carries a 12-bit VLAN ID and the 3-bit CoS.
  • Native VLAN frames are untagged, so they carry no CoS.
  • Ranges: 1 default · 2–1001 normal · 1002–1005 reserved · extended above.
  • DTP: auto + auto = access; desirable or trunk on either side = trunk; access + trunk = do not use.
  • In the final: autonomous AP with several SSIDs → trunk; LAP → access port, WLC → trunk; RSPAN VLAN on trunks only.

05 VTP

  • Server creates VLANs and sends updates · client syncs and forwards, cannot create · transparent keeps local VLANs and only forwards updates.
  • Higher revision number wins: adding a switch with a higher revision can wipe the domain's VLANs. Password = MD5.
  • VTP can carry the RSPAN VLAN; pruning keeps it off trunks that do not need it.

06 EtherChannel

  • Bundles links into one logical port, so STP sees one link.
  • PAgP (Cisco): desirable starts, auto waits. LACP (802.3ad): active starts, passive waits. on works only with on.
  • Never bundles: auto + auto, passive + passive. Members must match speed, duplex, VLANs, trunk mode.
  • In the final: MEC = one EtherChannel to two physical switches (VSS / StackWise) → no STP blocking; a failed member only cuts capacity.

07 Multilayer switch

  • Switchport = L2; no switchport = routed L3 port.
  • SVI (interface vlan 10) = the VLAN's gateway; up only if the VLAN exists with an active port. Needs ip routing.
  • In the final: the SVI is the DHCP default-router, where ip helper-address goes, and where HSRP runs.

08 Inter-VLAN routing

  • Router-on-a-stick: one trunk, subinterfaces; encapsulation dot1Q 10 before the IP address.
  • L3 switch with SVIs: faster and scales better.

09 Private VLANs

  • Primary VLAN holds secondary VLANs. Isolated ports talk only to promiscuous; community ports talk within the community and to promiscuous; promiscuous (gateway) talks to everyone.

10 STP

  • Root = lowest bridge ID (priority, default 32768 in steps of 4096, then MAC).
  • Each non-root switch: one root port (lowest cost to root). Each segment: one designated port. The rest block.
  • Cost 10M / 100M / 1G / 10G = 100 / 19 / 4 / 2.
  • Timers: hello 2 s, forward delay 15 s, max age 20 s. States: blocking → listening → learning → forwarding.
  • Direct failure 30 s; indirect about 50 s (max age + 2 × forward delay).
  • In the final: make the STP root and the HSRP active the same switch per VLAN. STP = lowest wins, HSRP = highest wins. Shared VLAN across a switch block → STP blocks uplinks.

10B BackboneFast

  • Detects an indirect failure with RLQ and skips the max-age wait (saves 20 s).

11 STP tuning and guards

  • spanning-tree vlan 10 root primary → 24576 (or 4096 below the current root); root secondary → 28672.
  • PortFast: host port forwards at once, so DHCP finishes at boot (no 169.254.x.x).
  • BPDU Guard: PortFast port receives a BPDU → err-disabled. Root Guard: port may never become root port.
  • UplinkFast: fast switch to the backup uplink; sets priority 49152, cost +3000.

12 Loop Guard and UDLD

  • Loop Guard: BPDUs stop arriving → loop-inconsistent instead of forwarding.
  • UDLD: detects one-way links; messages every 15 s, about 45 s to detect.

13 RSTP

  • States: discarding, learning, forwarding.
  • Roles: root, designated, alternate (backup path to the root), backup (second link to the same segment).
  • Proposal/agreement handshake: about 1 s. Neighbour lost after 3 missed hellos (about 6 s). Edge port = PortFast.

14 RSTP vs 802.1D

  • Blocking + listening merge into discarding; no timer waits on point-to-point links, so convergence is much faster.

15 MST

  • Many VLANs mapped onto a few instances = fewer STP trees.
  • Same region only if name, revision number and VLAN-to-instance map all match.

16 DHCP

  • DORA: Discover → Offer → Request → ACK. Client 68, server 67; Discover 0.0.0.0 → 255.255.255.255. Request is broadcast so the other servers know they were not chosen.
  • Pool: excluded-address → pool → network (subnet) → default-router (VLAN gateway) → dns-server → lease (default 1 day).
  • Relay: ip helper-address on the client-facing SVI; the server still needs a pool for that subnet.
  • 169.254.x.x = no DHCP reply · names fail = DNS · lease OK but remote fails = gateway.
  • SLAAC: host builds its address from the RA prefix. M = address from DHCPv6, O = DNS from DHCPv6. Needs ipv6 unicast-routing.

17 Campus design

  • Access = end devices, VLANs, port security · distribution = inter-VLAN routing, ACL, QoS, L2/L3 boundary · core = fast forwarding only.
  • Switch block = access + distribution pair; STP stays inside it; another block is reached through the core.
  • Shared VLAN → STP blocks · local VLANs + routed distribution link → no loop · routed access → all L3, both uplinks used.
  • Dual core · multinode (very large) · collapsed core (distribution + core on one pair, smaller site).

18 WLAN

  • Half-duplex, CSMA/CA: DIFS + random backoff; collisions still possible.
  • BSS = one AP · ESS = many APs on the wired network · IBSS = ad hoc. SSID ↔ VLAN. More APs at lower power beats more power; channels 1, 6, 11.
  • Split-MAC: LAP = real-time radio; WLC = authentication, roaming, RF, QoS. CAPWAP control UDP 5246 (encrypted), data 5247 (DTLS optional).
  • Roaming: intra-controller <10 ms · L2 inter-controller <20 ms, same subnet · L3 inter-controller = anchor (old) + foreign (new), EoIP tunnel, IP kept.
  • Fast roaming: CCKM, OKC/PKC, 802.11r.

18B HSRP

  • Shared virtual IP + virtual MAC removes the gateway single point of failure.
  • Active = highest priority (default 100), then highest IP. Preempt is OFF by default.
  • Hello 3 s, hold 10 s; new active sends gratuitous ARP; hosts change nothing.
  • vMAC v1 0000.0C07.ACxx, v2 0000.0C9F.Fxxx, group in hex (10 = 0A, 30 = 1E). v1 groups 0–255 / 224.0.0.2; v2 0–4095 / 224.0.0.102.
  • Both routers Active = hellos lost (group/version mismatch, link). VRRP = standard master/backup; GLBP = per-host load balancing.

19 High availability

  • Logical switch → EtherChannel → no STP blocking. MEC = members on different chassis.
  • StackWise up to 9 switches; VSS = 2 chassis + VSL.
  • RPR reloads modules (>2 min) · RPR+ keeps modules (>30 s) · SSO fully synced (~1 s, links stay up).
  • NSF + SSO: keep forwarding from the FIB while the RIB is rebuilt (BGP, EIGRP, OSPF, IS-IS).

20 QoS

  • Voice: delay <150 ms, jitter <30 ms, loss <1%. IntServ = hard (RSVP); DiffServ = soft, by class, scales.
  • DSCP 6 bits. AFxy = 8x + 2y · EF = 46 · CSn = 8n. Higher drop value = dropped sooner. Decode: ÷8 = class, remainder ÷2 = drop (28 = AF32, 30 = AF33).
  • Untrusted port → DSCP 0. Trust CoS → CoS × 8 (CoS 5 → 40, not 46).
  • Shaping delays excess (use toward an ISP that polices); policing drops or re-marks.
  • WRR share = weight ÷ total; voice in the priority queue. Tail drop → TCP synchronization; WRED drops early and randomly by DSCP.

21 Monitoring

  • Syslog 0 emergencies · 1 alerts · 2 critical · 3 errors · 4 warnings · 5 notifications · 6 informational · 7 debugging. Threshold shows itself and lower numbers; console default 7.
  • Boot clock March 1, 1993. clock set = privileged EXEC; clock timezone = global config.
  • NTP stratum = the * peer + 1; 16 = unsynchronized.
  • SNMP: get/set to UDP 161; trap/inform to UDP 162; informs are acknowledged (v2c+). v3 levels noauth / auth / priv; order group → user → host.
  • SPAN: destination port has STP off, never connect it to the network. RSPAN: remote-span VLAN on every switch's trunks; middle switch needs only the VLAN.

22 Security

  • CIA: confidentiality = who can read · integrity = who can change · availability = reachable when needed.
  • Firewall (inline): inside → outside OK · outside → DMZ OK · outside → inside denied · DMZ → inside denied unless permitted.
  • IPS = inline, signature-based, blocks · IDS = watches a copy, alerts.
  • NGFW = firewall + AVC + malware protection + URL filtering + IPS · NGIPS adds context, reputation, impact levels.

practice density

The sequence deliberately revisits Spanning Tree from four angles: manual calculation, verification, configuration, and topology change.

Use the repetitionLAB 07, LAB 08, LAB 09 and LAB 10 share one topology. Solve it on paper first, confirm it in IOS, change the priorities, then observe convergence.

The five sentences that hold the system together

  1. A switch floods what it does not know — which is why loops are fatal and why VLANs reduce risk.
  2. A VLAN is a broadcast domain, and a broadcast domain is a subnet — so crossing VLANs is always a layer 3 act.
  3. Redundant links are mandatory and dangerous, so STP blocks the minimum to keep exactly one path.
  4. In STP, lowest always wins: priority, then MAC, then cost, then sender BID, then sender port.
  5. Every convergence feature exists to remove one specific wait — PortFast, UplinkFast, BackboneFast, and finally RSTP removes them all.

Intro & Design Model

Campus Design · Hierarchy

Big networks are built in layers so they can grow and be fixed.

Technical scope

The console centers on Layer 2 switching and the Layer 3 functions that connect switched domains: VLANs, inter-VLAN routing, VTP, EtherChannel, Private VLANs, Spanning Tree, DHCP, campus design, basic QoS, high availability, and wireless design.

The slide also asks: "What about Spine and Leaf?" — the modern data-center answer. Every leaf switch connects to every spine, so any server is exactly two hops from any other. It exists because data-center traffic is now mostly east-west (server to server), while the 3-layer model was designed for north-south traffic (user to internet).

02

IPv6

IPv6 · EUI-64 · SLAAC

128-bit addresses. Written as 8 hex groups, shortened by two rules.

The problem

IPv4 has 2³² addresses and ran out. IPv6 has 2¹²⁸ — enough that every device can have a public address again, which kills the need for NAT. Adoption is now roughly half of Google's traffic; the slide shows the IPv4→IPv6 overlap running through the 2020s and 2030s.

Writing an address

  1. 128 bits = 8 groups ("quartets") of 4 hex digits: 2001:DEAD:CAFE:0000:0000:0000:0007:0088
  2. Drop leading zeros in each group: 2001:DEAD:CAFE:0:0:0:7:88
  3. Replace one run of all-zero groups with :: — 2001:DEAD:CAFE::7:88

Only one :: per address, because with two you couldn't tell how many zero groups each one hides.

EUI-64 — build the host part from a MAC

  1. Split the 6-byte MAC in half.
  2. Insert FFFE between the halves.
  3. Flip the 7th bit from the left of the first byte (0↔1).

0013.1234.ABCD → 001312 | 34ABCD → 0013:12FF:FE34:ABCD → flip → 0213:12FF:FE34:ABCD

Shortcut for the flipThat bit means "locally administered". Flipping it changes the first byte by ±2 in hex: 00↔02, 12↔10, CC↔CE, AB↔A9. Practise on 0200.0101.0101 → link-local FE80::1FF:FE01:101.

The three devices

The five behaviours of a transparent bridge

  1. Listen — read the source MAC of every frame and record it against the port it arrived on.
  2. Update — if a MAC appears on a new port, move the entry.
  3. Flood broadcasts — out every port except the one it came in on.
  4. Flood unknown unicast — destination not in the table? Same treatment.
  5. Never modify the frame — which is exactly why it's called transparent.
Why this matters laterBehaviours 3 and 4 are what make bridging loops catastrophic. They are the entire motivation for Spanning Tree in Topic 10.

The MAC table

  • Cisco calls it CAM (Content-Addressable Memory). Entries age out after 300 s.
  • TCAM is a separate, ternary version used for ACL lookups — it can match "don't care" bits.

The problem

A LAN is "everyone in the same broadcast domain", and by default a whole switch is one LAN. To split it you'd need a second physical switch — expensive and inflexible. A VLAN does it in software.

VTP

Create a VLAN once; the domain copies it everywhere.

The problem

With 50 switches you'd type vlan 30 fifty times, and one typo breaks connectivity in a way that's painful to find. VTP carries VLAN additions, deletions and renames in layer-2 frames along trunk links.

Domains

  • A domain is one switch or a group of interconnected switches sharing a domain name.
  • A switch belongs to exactly one domain. By default it has none until you set it or it learns one.
  • VTP advertisements cannot cross a router — it is a layer-2 protocol on trunks.

The three modes

The subtlety students missTransparent still forwards other switches' advertisements — it just doesn't apply them to itself. So a transparent switch in the middle never breaks the domain behind it. That is exactly what Lab 03 makes you observe.

Pruning

By default a trunk carries traffic for every allowed VLAN. If the switch at the far end has no ports in VLAN 3, sending VLAN 3 broadcasts down that trunk is wasted bandwidth. VTP pruning stops broadcasts and unknown unicast for VLANs the neighbour doesn't need.

Link Aggregation / EtherChannel

EtherChannel · LACP · PAgP

Several cables acting as one link — more bandwidth, no STP drama.

The problem

A link is saturated. Two options: buy faster ports (expensive), or bundle the links you already have. Cisco calls the bundle an EtherChannel; the port-channel interface is the logical link you then configure.

Why you can't just plug in two cablesTwo parallel links between switches form a loop, so Spanning Tree blocks all but one. You get redundancy but zero extra bandwidth. EtherChannel makes STP see a single logical link, so every member forwards.

Four benefits

  • No hardware upgrade needed — reuse existing ports.
  • Configure once, on the port-channel interface.
  • Redundancy without reconvergence: losing one member does not change the topology, so STP does not recalculate.
  • Load balancing across members of the same channel.

Spanning Tree Protocol

STP · Root Election · Port Roles

Redundant links create loops. STP blocks the minimum number of ports to break every loop.

Why a loop is fatal — walk it through

Two switches A and B both connect segment A to segment B. PC1 (segment A) sends one frame to PC4, and neither switch knows either MAC yet:

  1. A and B both receive it on gi1/0/1 and record PC1 → port 1/0/1.
  2. Both decide to flood it.
  3. Both flood it onto segment B. PC4 gets two copies — and A hears B's copy while B hears A's.
  4. Both now relearn PC1 → port 1/0/2. The MAC table has flipped.
  5. Still nobody knows PC4, so both flood again — back onto segment A.
  6. Relearn, reflood, forever. One frame becomes an infinite storm.
Three simultaneous failuresBroadcast storm eats all bandwidth · MAC tables thrash so unicast is unreliable · every host is interrupted by duplicate frames. A single loop can take down a building, which is why STP is on by default everywhere.

How switches recognise each other: the BID

Bridge ID = 8 bytes: a 2-byte priority field followed by the 6-byte system MAC. Lower is better, and priority is compared first — the MAC only breaks ties.

BPDUs — the messages

  • Sent to the multicast address 01-80-C2-00-00-00, source = the switch's own MAC, every 2 seconds by default.
  • Configuration BPDU — builds and maintains the tree.
  • TCN BPDU — announces that something changed.

The algorithm — three elections

  1. One root bridge per VLAN (with PVST+). Every port on the root becomes designated.
  2. One root port on each non-root switch — its best way back to the root.
  3. One designated port per network segment — the end closer to the root.

Anything that is neither a root port nor a designated port is blocked.

Election 1 — the root bridge

Every switch boots believing it is the root and advertises itself. As better BPDUs arrive they defer. Winner = lowest priority, tie → lowest MAC. A new switch with a lower BID can preempt an existing root at any time, which is why you set priorities manually (Topic 11).

Election 2 — root ports, and how cost accumulates

  1. The root sends BPDUs with root path cost 0.
  2. A neighbour receives it and adds the cost of the port it arrived on.
  3. It re-advertises with the new cumulative cost, and so on outward.

Three kinds of topology change

1 · Direct — the switch physically sees a link go down.

  1. A and C both detect the link down.
  2. C removes its stored best BPDU and tries to send a TCN out its root port — but that was the failed link.
  3. A (the root) sends a BPDU with the TC flag set; every switch relays it.
  4. B and C shorten their MAC ageing from 300 s to 15 s so stale entries die fast.
  5. C's blocked port becomes its best path and walks blocking → listening → learning → forwarding.

Downtime = 2 × Forward Delay = 30 s

2 · Indirect — the link stays up but traffic silently stops (a one-way failure).

  1. Both ends still show "up", so no failure is detected and no TCN is sent.
  2. C keeps its stored BPDU until Max Age expires and flushes it.
  3. C waits to hear from the root again, and gets a configuration BPDU on its blocked port.
  4. That becomes the new best entry; the port walks blocking → listening → learning → forwarding.

Downtime = 20 + 2 + 15 + 15 = 52 s

3 · Insignificant — cosmetic, e.g. a user reboots their PC.

  1. C sees the access port go down and sends a TCN to the root.
  2. The root acknowledges and floods a TC-flagged BPDU to everyone.
  3. Every switch shortens MAC ageing and flushes idle entries — for no reason at all.
This is the argument for PortFastA cosmetic event just aged out the whole network's MAC tables. Topic 11's PortFast stops host ports from generating topology changes, and LAB 10 makes you watch both behaviours back to back.

BackboneFast & RLQ

BackboneFast · RLQ · Indirect Failure

Kill the 20-second Max Age wait after an indirect failure — by asking upstream "can you still reach the root?"

What it is for

  • BackboneFast exists only for indirect failures — a link that dies somewhere you cannot see.
  • It removes the Max Age timeout (20 s).
  • It does not remove Listening and Learning, so you still pay 15 + 15.
  • Result: recovery drops from 52 s to about 30 s.

The inferior BPDU — where it comes from

When a switch loses its connection to the root, it does the only thing it can: it declares itself the new root and advertises that. Since its claim is worse than the information neighbours already hold, that message is called an inferior BPDU. It is not a lie — it is a cry for help, and BackboneFast is the mechanism that hears it.

Without BackboneFast — why it takes 20 extra seconds

  1. The A–B link fails indirectly. A never notices, so A sends no topology change.
  2. B notices it has lost the root, declares itself root, and sends an inferior BPDU out of e3 toward C's port e4.
  3. C's e4 is a blocked port. C ignores the inferior BPDU and simply keeps waiting — until the good BPDU it stored from A expires after 20 s (Max Age). Only then does e4 begin Listening and the tree rebuilds.
The wasteC had a perfectly good path to the root the whole time. It just had no way to ask, so it sat out the full Max Age timer doing nothing.

With BackboneFast — the RLQ conversation

  1. Same indirect failure at A–B; A still says nothing.
  2. B still declares itself root and sends the inferior BPDU to C.
  3. C receives an inferior BPDU on a blocked port — the trigger. C immediately sends a Root Link Query (RLQ) out of its other candidate ports.
  4. An RLQ Reply (RLQ R) comes back, confirming C can still reach the real root.
  5. C moves e4 straight to Listening. No 20-second wait.

RLQ rules — memorise these two lists

A switch that receives an RLQ…does this

is the root bridgesends RLQ R back down the spanning-tree path
has also lost the rootsends the reply straight back to that port (bad news travels fast)
The switch that sent the RLQ gets the reply…does this
on its root portIts own tree is unchanged. It just moves the port that received the inferior BPDU to Listening.
on a blocked portThat blocked port may become the new root port. It moves both the blocked port and the inferior-BPDU port to Listening — and lets the normal election decide which one wins.

The worked example from the slides

Implementing STP 2 — Loop Guard, UDLD, Flex Links

Loop Guard · UDLD · Flex Links

The dangerous failure is not a broken link — it's a link that goes quiet.

First, the complete list of port roles

RoleDefinition
Root portThe one port on a switch closest to the root bridge
Designated portThe port on a segment that is closer to the root
Blocking portNeither root nor designated
Alternate portA candidate root port sitting in blocking — identified for fast reuse by UplinkFast
Forwarding portPorts where no STP activity is expected — normal end-user connections

The silent-failure problem

STP trusts BPDUs completely. A blocked port that stops receiving them assumes the topology changed: after Max Age it flushes the stored BPDU, transitions through the states, and starts forwarding. If the BPDUs stopped because of a fault rather than a real change, that port has just closed a loop. Worse, it now believes it is designated and starts sending BPDUs downstream when it should be listening upstream.

Loop Guard

  • Watches non-designated ports. If BPDUs stop arriving, the port goes to loop-inconsistent blocking instead of forwarding.
  • Recovers by itself the moment BPDUs return — no manual reset.
  • Safe to enable everywhere: the switch works out which ports are non-designated on its own.
  • Layer 2 only.

SPANTREE-2-LOOPGUARDBLOCK: No BPDUs were received on port 3/2 in vlan 3. Moved to loop-inconsistent state.
SPANTREE-2-LOOPGUARDUNBLOCK: port 3/2 restored in vlan 3.

UDLD — proving the link works both ways

Fibre uses two strands, and SFP/GBIC modules fail one direction at a time. Both switches still see "link up", but traffic only flows one way. UDLD sends layer-2 frames carrying the sender's port identity; the far end must echo them back with its own identity added. If that round trip completes, the link is genuinely bidirectional.

Rapid Spanning Tree — How It Works

RSTP · Proposal/Agreement · Edge

Same tree, built by handshakes rather than by waiting out timers.

Where it came from

802.1w evolved 802.1D for faster convergence. Cisco combined it with PVST+ to get Rapid PVST+ (also written RPVST+ or PVRST+), configured as rapid-pvst. RSTP is also the foundation of 802.1s MST. Root bridge election is unchanged from 802.1D — same BID, same lowest-wins rule.

Port roles — two new ones

RoleMeaning
RootBest path to the root — same as 802.1D
DesignatedThe segment's best port toward the root
AlternateAn alternate path to the root via another switch — blocked, but ready
BackupA redundant, less desirable connection to the same segment — blocked

Alternate = "if my root port dies I'll use this to reach a different switch". Backup = "my second cable onto the same wire". Backup only exists with hubs or shared segments, so it is rare in practice.

Port states — five become three

802.1DRSTPFramesLearns MACs

Port types

TypeDefinition
Edge portAt the edge of the network with a single host attached — i.e. PortFast. Loses edge status the instant a BPDU arrives
Root portThe port with the best cost to the root
Point-to-pointConnects to another switch and becomes designated. Full-duplex links are assumed point-to-point

RSTP treats convergence as a chain of handshakes across point-to-point links — which is exactly why the port type matters.

Faster failure detection

  • Every switch sends its own BPDUs every hello interval, rather than only relaying the root's.
  • Miss 3 in a row and the neighbour is presumed down; all information about that port is aged out immediately.
  • That is ≈ 6 seconds, versus Max Age 20 seconds in 802.1D.

Synchronisation — the proposal/agreement handshake

After BPDU exchange identifies the root, a switch receiving a superior BPDU makes that port its root port. For each non-edge port it then runs this sequence:

  1. The sender has a superior BPDU, so the local switch accepts it as the designated switch and makes its own port the new root port.
  2. It synchronises itself with the topology.
  3. All non-edge ports move to Discarding — the switch deliberately isolates itself.
  4. It sends an agreement back, confirming the designated-port choice.
  5. The root port moves to Forwarding; the sender's port can forward too.
  6. For each non-edge port still discarding, it sends a proposal to that neighbour.
  7. It expects and receives an agreement back.
  8. That port moves to Forwarding.
Why this is safe and fastBefore agreeing, a switch blocks everything downstream. At no instant does a path exist that could form a loop — so there is no need to wait 15 + 15 seconds "just in case". The blocking travels outward like a zipper, and each link comes up in milliseconds.

RSTP 2 — Roles & Topology Changes in Practice

RSTP · Roles · Topology Changes

The same event, told twice: 802.1D takes 30 seconds, RSTP takes a handshake.

Reading a port-role diagram

The slide labels every port R (root), D (designated), A (alternate) or B (backup). Practise until you can label a diagram without thinking:

  1. Mark the root bridge — every port on it is D.
  2. On each other switch mark exactly one R (best cost home).
  3. On each link, the end closer to the root is D.
  4. A leftover port facing another switch is A; a leftover second port onto the same segment is B.

The TC mechanism, step by step

When a bridge detects a change:

  1. It starts the TC While timer (2 × hello) on all non-edge designated ports and, if needed, its root port. That timer is how long it actively advertises the change.
  2. It flushes the MAC addresses associated with those non-edge ports.
  3. While the timer runs, every BPDU it sends carries the TC bit — including out of its root port.

When a bridge receives a TC BPDU:

  1. It clears MAC addresses on all its ports except the one the TC arrived on.
  2. It starts its own TC While timer and sends TC-flagged BPDUs out all designated ports and its root port.

The result: propagation is a one-step flood from whoever noticed, instead of 802.1D's two-step "notify the root, root notifies everyone". No waiting on the root at all.

Case study — adding a link between the root and switch A

Say this out loud before the exam"In 802.1D the port waits out Listening and Learning while the news spreads. That single paragraph answers any RSTP-vs-STP question.

  • A neighbour that knows a better path can refuse a proposal, leaving that link blocked.

The insight: with a given physical layout there are usually only two or three sensible topologies. Running a separate instance for every VLAN computes the same answers over and over.

Designing an MST deployment

  1. Decide how many instances you need — usually one per useful topology (often 2).
  2. Decide which VLANs map to each instance.
  3. Root a different switch for each instance, so every uplink carries traffic.

DHCP & Relay

Addressing · Pools · SLAAC

Dynamic Host Configuration Protocol (DHCP) gives a host an IP address and the settings it needs to use the network. A relay lets clients reach a server in another subnet.

What the client receives

A lease is permission to use an address for a limited time. Along with that address, a DHCP server can supply the subnet mask, default gateway, and Domain Name System (DNS) servers. The gateway reaches other networks; DNS resolves names. They solve different problems.

First understand the boundaryA client's initial broadcast stays inside its VLAN. A local DHCP server can answer directly. To reach a central server across a Layer 3 boundary, configure a DHCP relay on the client's gateway interface.

DORA: follow one new lease

Choose a message to see who sends it and why. DORA means Discover → Offer → Request → Acknowledge. User Datagram Protocol (UDP) port 67 belongs to the server; port 68 belongs to the client.

Client → local broadcast

0.0.0.0 : 68 → 255.255.255.255 : 67

“Is a DHCP server available?” The client has no usable IPv4 address yet, so it broadcasts a DHCPDISCOVER.

Server → client

Server IP : 67 → client / broadcast : 68

A DHCPOFFER proposes an address and configuration. Several servers can offer a lease; the client chooses one. The slide example shows a broadcast reply.

Client → local broadcast

0.0.0.0 : 68 → 255.255.255.255 : 67

The client broadcasts a DHCPREQUEST identifying its selected offer. This tells the other servers that their offers were not selected. This is the initial selection step, not lease renewal.

Server → client

Server IP : 67 → client / broadcast : 68

A DHCPACK confirms the lease and settings. The client can then configure the address. An offer alone is not the completed lease.

The slides draw all four messages as broadcasts. In real networks the server may send the Offer and ACK straight to the client (unicast) instead, and lease renewals are normally unicast. See RFC 2131, message delivery.

Configure a local DHCP server

  1. Check the gateway first. The VLAN needs a working gateway interface: an SVI such as interface vlan 10 on a multilayer switch, or a router subinterface.
  2. Exclude fixed addresses. Addresses already used by the gateway, servers or printers must be excluded so DHCP never hands them to a client.
  3. Create a named pool. Enter the subnet, then the gateway, DNS server and lease time that clients should receive.
  4. One pool per VLAN. Each VLAN subnet needs its own pool. The server chooses the pool whose subnet matches the interface the request arrived on; for a relayed request, it uses the relay interface address (for example 10.1.10.1).
Example: a pool for VLAN 10
ip dhcp excluded-address 10.1.10.1 10.1.10.20   ! range: .1 through .20
ip dhcp excluded-address 10.1.10.254             ! a single address
ip dhcp pool VLAN10

 default-router 10.1.10.1
 dns-server 8.8.8.8 8.8.4.4                      ! one or two servers

 exit

Enterprise Campus Network Design

Hierarchy · Modules · Resilience

A campus network should grow and recover in predictable ways. Give each layer a clear job, group access and distribution switches into blocks, and provide deliberate redundant paths.

From one shared segment to a hierarchy

The first slide shows an old shared Ethernet segment (a hub): all hosts share the same bandwidth and are in one collision domain and one broadcast domain. A switch gives every port its own collision domain; a router or Layer 3 switch splits broadcast domains. So the collision problem on that slide does not apply to modern switched networks.

When a network grows without a plan, nobody can tell which path traffic takes. A good design knows where traffic flows, has enough capacity, has room to grow, and has a known plan for failures.

A switch block limits the failure domain

A switch block is a group of access switches plus the distribution switches they connect to. The core connects the switch blocks together. Usually routing starts at the distribution switches: VLANs and broadcasts stop there, so Spanning Tree Protocol (STP) runs only inside each block.

A second cable does not protect against failure of the only upstream switch. Use a pair of distribution switches, with each access switch connected to both. A separate core also needs redundancy; one core switch would remain a single point of failure.

Compare three switch-block designs

Pick a design and see where routing (Layer 3) begins. All three use the slides' layout: two distribution switches above two access switches.

Shared VLAN · larger Layer 2 domain

VLAN A is on both access switches, so it must be carried on trunks between all four switches. That creates loops, and STP has to block some links.

Local VLANs · smaller Layer 2 domains

VLAN A exists only on the left access switch and VLAN B only on the right. The access uplinks are still Layer 2 trunks, but the link between the two distribution switches is routed (Layer 3). There is no Layer 2 path between the access switches, so there is no loop for STP to block.

Routed access · Layer 3 moves down

The access switches now route. Their uplinks and the distribution link are all Layer 3. If an uplink fails, the routing protocol (for example OSPF) switches to the other one, and both uplinks can carry traffic at the same time. VLANs exist only on each access switch.

Size the block by traffic, not just headcount

  • Access capacity: enough ports for users and devices, plus uplink capacity for their traffic.
  • Distribution capacity: all traffic from the access switches, plus routing between VLANs, plus ACL and QoS processing.
  • VLAN size: how far each VLAN stretches, how much broadcast and multicast traffic it carries, and how large the STP domain becomes.
  • Growth: which user groups and applications will be added, and where their servers are.

The slides give about 2,000 users per block as a historical sizing guideline. It is not a protocol limit. Traffic behavior and device capacity decide when to split a block.

Signs the block is too largeThe distribution switches are overloaded by routing or ACL work, or broadcast and multicast traffic slows the whole block. Fix it by adding capacity or splitting the block; adding more access ports only makes it worse.

Design review: explain every link

  1. Mark the access, distribution, and core roles.
  2. Draw the VLAN and Layer 3 boundaries. Identify which links are trunks and which are routed.
  3. Give each access switch two upstream paths to distinct distribution switches.
  4. Link the two distribution switches together. Do not link access switches to each other, unless they are stacked into one logical switch.
  5. Test both a link failure and a switch failure, and know which protocol recovers (STP, HSRP or the routing protocol).
  6. After a failure, the remaining link carries all the traffic. Make sure it is big enough.
Check yourself: two access uplinks end on one distribution switch. Is that enough?

Integrating Wireless LAN

RF · CAPWAP · Roaming

In a wireless LAN, all devices on a channel share the same radio time. The access point (AP) links wireless clients to the wired network. The design you choose (autonomous or controller-based) decides where traffic goes, where settings are managed, and how a moving client stays connected.

Shared airtime: CSMA/CA and backoff

Wi-Fi is half-duplex: on one channel, only one device can transmit at a time. Devices use Carrier Sense Multiple Access with Collision Avoidance (CSMA/CA): listen first, then wait a random time before sending, so two devices are less likely to transmit together.

  1. Wait for the channel to become idle, then wait the Distributed Coordination Function Interframe Space (DIFS).
  2. Count down a random backoff while the channel stays idle.
  3. If another device starts transmitting, pause the countdown. Continue counting when the channel is free again.
  4. Transmit when the counter reaches zero. Collisions can still occur, for example when two counters expire together.

In the slide's A/B/C example, A transmits first; B and C defer. C's shorter backoff wins the next turn, so B waits again. Collision avoidance reduces the risk; it does not promise that collisions never happen.

An Access Point (AP) connects wireless and wired traffic. In normal (infrastructure) mode, clients never talk directly: even two clients on the same AP send their traffic through the AP. Direct Link Setup is a special exception.

Cells, channel reuse, and BSS coloring

A cell is one AP's coverage area. Neighboring cells should overlap a little so clients can roam, with no gaps (coverage holes). The slides compare a grid layout with a honeycomb layout, and also plan channels between floors, because APs on the floor above and below interfere too.

  • Coverage is not the same as capacity. Full power covers a bigger area, but then more clients share one AP's airtime, so each client gets less.
  • Smaller cells can support a denser deployment. The slides call reduced-power cells microcells and very small cells picocells.
  • Plan channels. Two nearby APs on the same channel share airtime and slow each other down, so neighbors should use different non-overlapping channels (1, 6 and 11 on 2.4 GHz).
  • BSS coloring (Wi-Fi 6) puts a 6-bit "color" number in the frame's first part (the PHY header). A device can then tell quickly whether a frame comes from its own AP or a neighbor's, without reading the full 48-bit BSSID.
Different color is not automatic permissionIf a frame comes from a neighbor's BSS (different color) and its signal is weak, a device may transmit anyway instead of waiting. It still follows normal CSMA/CA. The color is only a label; it gives no security.

Split-MAC: divide the work

Split-MAC (Cisco Unified Wireless Network, CUWN) divides the work that one autonomous AP does alone between two separate devices. A lightweight AP (LAP) is an AP that cannot work alone; it needs a wireless LAN controller (WLC), a separate device that manages many LAPs. The LAP keeps the real-time radio work: sending and receiving frames, beacons and probe replies, and Wi-Fi encryption. The WLC does everything else: authentication, security policy, association and roaming, RF channel and power, and QoS.

Control and Provisioning of Wireless Access Points (CAPWAP) is the protocol between the LAP and the WLC. It runs over IP, so the LAP and WLC can be in different subnets. It replaced the older Lightweight Access Point Protocol (LWAPP). CAPWAP uses two tunnels:

TunnelCarriesProtection in the slide model

The LAP and WLC prove who they are to each other with X.509 certificates. Note the difference: Wi-Fi encryption (WPA2/WPA3) protects client ↔ AP, while CAPWAP DTLS protects AP ↔ WLC. They are separate.

The WLC can also choose channels and power automatically, raise power to cover a failed AP's area, spread clients across APs, monitor the radio environment, and detect wireless attacks.

How a lightweight AP becomes ready

  1. Get an IP address from DHCP.
  2. Discover available controllers and learn their addresses.
  3. Join a controller. If it cannot join the first one, it tries the next.
  4. Match the software image. If needed, download the controller-provided image and reboot.
  5. Build the secure CAPWAP tunnel and download its settings (SSIDs, VLANs, channels).

In the slides' model, if a LAP loses its WLC, its clients are disconnected and the LAP looks for another WLC. Some AP modes (such as FlexConnect) and backup controllers can keep clients working.

First Hop Redundancy & HSRP

Gateway · Virtual IP · Failover

A host sends every off-subnet packet to one default gateway. A First Hop Redundancy Protocol (FHRP) lets two or more routers share a virtual gateway address, so one router can fail without reconfiguring any host.

The gateway is a single point of failure

In the supplied example, hosts in VLAN 10 (10.1.1.0/24) use R1 at 10.1.1.9 as their default gateway. Redundant switch links do not help when R1, or its LAN interface, fails: nothing can leave the subnet.

Adding R2 at 10.1.1.129 creates a second exit, but a host still has only one configured gateway. Hosts pointing at .9 keep sending to a dead router. Changing every host, or waiting for new DHCP leases, is not a failover plan.

The FHRP ideaThe routers keep their own interface addresses and also share a virtual IP address and virtual MAC address. Hosts use the virtual IP as their gateway. One router normally answers for it; another takes over when that router fails.

Follow one HSRP failover

Choose a stage. The hosts' configuration never changes: every host keeps gateway 10.1.1.1 and the same ARP entry for it.

R1 is active and owns the virtual gateway

R1 wins the active role with priority 110 against R2's default 100. Only the active router uses the virtual IP and virtual MAC. R2 monitors R1's hellos and is ready to take over.

R2 becomes active; the hosts change nothing

R2 stops hearing hellos; when the hold time expires (10 s by default, with 3 s hellos) it becomes active and starts using 10.1.1.1 and 0000.0C9F.F001. It sends a gratuitous ARP — an ARP reply nobody requested — sourced from the virtual MAC. The switches update their MAC address tables, so frames for the gateway now go out the port toward R2.

Preemption decides whether R1 takes the role back
R1 configurationResult when R1 recovers
standby 1 priority 110 onlyR2 stays active. Without preemption, an existing active router keeps its role even if a higher-priority router appears. R1 becomes standby.
standby 1 priority 110 + standby 1 preemptR1 preempts and becomes active again; R2 returns to standby.

Preemption is off by default in HSRP and is configured on the router that should reclaim the role. In show standby brief, a P beside the priority marks a router configured to preempt.

Which router becomes active?

  1. No other HSRP router on the subnet: the local router becomes active.
  2. No active router yet, several candidates: the highest priority wins. Default priority is 100.
  3. Priorities tie: the highest IP address on the HSRP interface wins.
  4. An active router already exists: it keeps the role unless a higher-priority router is configured with preempt.
Exam trap“Highest priority is always active” is false. Without preemption, the router that became active first stays active. Also note that HSRP uses the highest values, while STP elections use the lowest.

High Availability

Logical switches · Supervisors · NSF

High availability (HA) means the network keeps working almost all the time, even when a part fails. In a campus you get it from: two of every device, two of every link, joining switch pairs into one logical switch (so STP blocks nothing), and a backup supervisor that takes over quickly.

Pairs at every layer — and what they still waste

The campus design rule is to build each layer in pairs and connect each lower switch to the next layer with two links. In the supplied figure, every access switch has an uplink to each distribution switch. That survives a link or distribution-switch failure, but two problems remain:

  • The two access switches do not back each other up; a host plugged into one depends on that one switch.
  • The redundant uplinks form loops, so STP blocks some of the bandwidth you paid for.

The improvement is to make two physical switches behave as one logical switch. Links to a logical switch can be bundled into one EtherChannel, and STP sees one link rather than a loop.

Three stages of the same switch block

Four independent switches · STP blocks uplinks

Every switch is managed separately. Failover depends on STP reconverging, and blocked uplinks add no capacity during normal operation.

One logical access switch · one EtherChannel per distribution switch

A1 and A2 now back each other up and bundle their uplinks. But D1 and D2 are still separate switches, so the two EtherChannels form a loop through them, and STP may block one whole channel.

Two logical switches · one multichassis EtherChannel

Between two logical switches there is no Layer 2 loop to break, so nothing is blocked. All links carry traffic, and losing one physical switch or link only reduces the channel's capacity.

StackWise: many access switches, one logical switch

  • Cisco StackWise / StackWise Plus joins separate physical switches with special stacking cables, daisy-chained back to the first switch to close a ring.
  • Up to nine physical switches can form one stack in the deck's model.
  • One member is the stack master: it performs management for the whole stack, which is managed through one IP address.
  • The deck's examples are fixed-configuration access switches such as the Catalyst 3750-E, 3750-X, and 3850.

Virtual Switching System: two chassis, one logical switch

  • A chassis switch has slots for line cards plus a supervisor card: the "brain" that runs management, routing protocols and the forwarding tables.
  • Virtual Switching System (VSS) configures two identical chassis as one logical switch, a VSS pair, joined by a virtual switch link (VSL).
  • One supervisor, in one chassis, controls the logical switch; the other chassis' supervisor is the redundant standby.
  • VSS is usually used at distribution or core. It is how you build the "logical distribution" switch in the third diagram above.
StackWise vs VSS in one lineStackWise stacks several fixed access switches with stack cables under a stack master. VSS pairs exactly two chassis over a VSL under one active supervisor. Both present one logical switch, enabling EtherChannels that span physical devices.

What QoS is for

  • Control over resources — for example, stop low-priority traffic from monopolizing a link.
  • More efficient use of resources — measure traffic, then decide how each class is handled.
  • Tailored services — offer different service grades to different customers or applications.
  • Coexistence of mission-critical applications — critical applications get the most efficient use of the network.

QoS deals with congestion. It fights three problems: delay (latency), jitter (changing delay), and packet loss. QoS cannot add bandwidth; it decides which traffic waits or is dropped when the link is full.

The Cisco switch QoS pipeline

  1. Classify each incoming packet: decide what kind of traffic it is and give it an internal DSCP value.
  2. Police: compare the traffic with its allowed rate; traffic above the rate is dropped or given a lower marking.
  3. Mark (or re-mark) the packet's QoS field.
  4. Choose a transmit queue for the egress interface.
  5. Congestion management decides which queue sends next; congestion avoidance (WRED) drops some packets early, before a queue is full.

Without a congestion-avoidance mechanism, a queue simply drops new packets when it is full.

  • Ways to classify: trust the marking arriving on a port; set one fixed value for everything on a port; match packets with an ACL; or recognize applications with Network-Based Application Recognition (NBAR).

WRR example: four queues with weights 50, 10, 25, 15 (total 100) get 50%, 10%, 25% and 15% of the bandwidth. If the weights do not add up to 100, a queue's share is its weight ÷ the total. Buffer memory is split too: priority queues get little (voice packets are small and leave immediately), while low-priority queues get more because their traffic waits longer.

LLQ (Low-Latency Queuing) is Cisco's name for adding one strict-priority queue to class-based queuing (CBWFQ): voice is always sent before packets in the other queues.

Congestion avoidance: tail drop, RED, WRED

Tail drop, the default, drops every arriving packet once the queue is full. That hurts TCP: many sessions lose packets together and enter slow start together (TCP synchronization), aggressive flows can monopolize the queue, deep queues add delay and jitter, and premium traffic is dropped just like best effort.

RED (Random Early Detection) drops a few packets at random before the queue is full; the fuller the queue, the more it drops. Only some TCP senders slow down each time, at different moments, so the link stays busy instead of every flow slowing down together. Once the queue is completely full, tail drop happens anyway. RED only helps TCP, because TCP slows down after a loss; UDP does not.

WRED (Weighted RED) adds classification: each IP Precedence or DSCP value can have its own minimum threshold, maximum threshold, and drop probability. Deck example for one queue: at 50% full, randomly drop DSCP 0–20 (best effort); at 80%, also drop DSCP above 20 (up to 31); when full, tail drop.

Best practicePut high-priority, delay-sensitive traffic in a strict priority queue and use WRR for the others; apply WRED to the remaining data queues. Use WRED on highly congested interfaces, especially WAN links between data centers.

AutoQoS: one command makes the switch create standard QoS classes and policies (for example for voice) automatically.

Check yourself: a packet arrives marked DSCP 30. What is it and how is it treated?

30 = 011110: class 011 = 3, drop 11 = 3 → AF33. It uses the class 3 queue with the highest drop priority, so WRED drops it before AF31 and AF32 traffic in that queue.

Check yourself: voice through a shaper — good idea?

No. Shaping buffers excess traffic, adding delay and jitter. Give voice a strict priority queue and police the priority class so it cannot starve the others.

Exam answer to rememberDiffServ classifies and marks at the edge (DSCP 6 bits, CoS 3 bits, IPP 3 bits), trusts markings only at the trust boundary, polices or shapes rates, schedules queues (priority for voice, WRR for the rest), and uses WRED instead of tail drop so TCP flows back off gradually.

Basic Security

CIA · Firewall · DMZ · IPS · NGFW

Security protects three properties of data: availability, integrity, and confidentiality. At the network edge, a firewall enforces which connections may cross between zones, a DMZ holds public servers, and an IPS looks inside traffic for known attacks.

The CIA (AIC) triad

PropertyMeaningExample threat
AvailabilityData and services can be reached reliably and on time.A denial-of-service (DoS) flood
IntegrityOnly authorized people or systems can change data.Altered configuration or records
ConfidentialityOnly authorized people or systems can access data.Eavesdropping on unencrypted traffic

Connect it to earlier topics: HA and HSRP serve availability; SNMPv3 authentication serves integrity; SNMPv3 encryption and SSH serve confidentiality.

Firewall

A firewall sits inline in the forwarding path between the internal network and the external network, so every packet crossing the edge passes through it. It chooses which packets to allow and which to discard, using rules that can match:

  • source and destination addresses;
  • transport-layer port numbers;
  • text in an HTTP request's URI;
  • TCP connection state — a stateful firewall remembers connections and allows the return traffic of sessions started from inside.

Security zones and the DMZ

A demilitarized zone (DMZ) is a less-secured zone for servers that outside users are allowed to reach, such as the public web servers for www.example.com. If a DMZ server is compromised, the attacker still has to pass the firewall to reach the inside zone.

IPS: matching attack signatures

A firewall filters by rules the administrator writes. An Intrusion Prevention System (IPS) uses different logic: it compares traffic with attack signatures — patterns of known attacks such as DoS, DDoS, viruses, and worms — and can drop matching packets or redirect them to another security application. An IPS is also placed inline between the external and internal networks. Its signature database must be kept updated.

One figure caption in the deck says “IDS.” An IDS (intrusion detection system) usually monitors a copy of traffic — for example from a SPAN port — and alerts, while an IPS sits inline and can block. The figure shows the inline IPS.

Block size = 256 − mask octet. Usable = block − 2 (network + broadcast). A /30 giving exactly 2 hosts is why router-to-router links use it — see Lab 05.

The four-step method

  1. Find the interesting octet — the one the prefix cuts through. /25–/30 cuts octet 4, /17–/24 cuts octet 3.
  2. Block size = 256 − that octet's mask value.
  3. Count up in blocks from 0 until you pass the host address. The last multiple you did not pass is the network address.
  4. Broadcast = next network − 1. Usable = network + 1 through broadcast − 1.

Traps
  • The mask is written /25 but typed 255.255.255.128. Packet Tracer wants the dotted form on PCs and the dotted form on ip address lines.
  • A switch management IP lives on interface vlan 1, not on a physical port — see Lab 01.
  • Two addresses in the same /24 are not automatically in the same subnet if the mask is longer. Always compute the network address before assuming reachability.
  • Point-to-point links take /30 (or /31 on real gear). Using /24 there wastes 252 addresses.
Why it mattersEvery subsequent lab silently assumes this. Lab 01 fails to ping if you read /25 as /24. Lab 05's OSPF adjacency will not form if the /30 is wrong on either end. This lab is short because it is a gate, not a topic.

Decoding the tag The 802.1Q tag is 4 bytes inserted after the source MAC. TPID is always 0x8100 — it is the flag that says "a tag follows". TCI is the next 16 bits, split PRI (3) · CFI/DEI (1) · VLAN ID (12). With default priority 0 and CFI 0, the TCI is just the VLAN number in hex:
VLAN 261 = 0x105 → TCI 0x0105  ·  VLAN 434 = 0x1B2 → TCI 0x01B2.
12 bits is why the VLAN range stops at 4094: 0 and 4095 are reserved.
Review checks

  • The native VLAN crosses the trunk untagged, and must match on both ends or traffic leaks between VLANs.
  • Cross-VLAN ping failing is correct behaviour. Fixing it needs a router — that is Lab 05.
  • Frame grows by 4 bytes, so the maximum tagged frame is 1522, not 1518.

The five-step method — use it every single time

  4. One Designated end per link: whichever side is closer to the root; tie → lower BID.

What you should see, and why

Three instances exist, not twenty. MST0 is the IST — it always exists and carries every VLAN you did not map, including VLANs 1–50 and 71–4094. MST1 carries 51–60, MST2 carries 61–70. Twenty VLANs, two trees plus the IST, instead of twenty independent computations.

Two different roots on one physical topology. Instance 1 folds toward IOU2, instance 2 folds toward IOU4. VLANs 51–60 and VLANs 61–70 take genuinely different paths across the same cables — that is load sharing, and it is the reason anyone bothers with MST instead of a single common tree.

Step 6 is the demonstration. The IOU2–IOU4 diagonal is the shortest hop between the two roots. Setting its instance-2 cost to 10,000,000 — far above any default long-path cost — forces instance 2 to reroute through IOU1 or IOU3, while instance 1 keeps using the diagonal at its normal cost. One cable, two costs, two behaviours, decided per instance.

Cost is set on both ends because path cost is evaluated on the receiving side; leaving one end cheap makes the two switches disagree about the diagonal.

Review checks
  • What makes a region. Three things must match exactly on every switch: name, revision number, and the VLAN-to-instance map. Not the priorities, not the costs. Mistype netdes as Netdes and you have two regions that talk to each other as if through plain 802.1D.
  • Instance 0 is the IST and cannot be deleted. Every unmapped VLAN rides it.
  • MST is built on RSTP, so it inherits the rapid transitions from Lab 11 — proposal/agreement, alternate ports promoted instantly.
  • The MST config is staged: your instance lines do nothing until you leave spanning-tree mst configuration mode. Then all of them apply at once and the tree re-converges.
  • Root election is per instance: spanning-tree mst 1 root primary touches instance 1 only.
  • Path cost is per instance too: spanning-tree mst 2 cost 10000000 leaves instance 1 alone on the same interface.
  • MST uses the long (32-bit) path cost method by default, which is why 10,000,000 is a plausible number here — under the old 16-bit short costs the maximum was 65,535.
  • Outside the region, the whole region looks like one single bridge to the rest of the network.
In the real worldA data-centre with 500 VLANs running PVST+ is running 500 spanning-tree processes, and the switch CPU feels every one. MST is how you get that down to two or three trees while still using both uplinks — half the VLANs left, half the VLANs right, nothing idle. The cost is that every switch in the region must be configured identically, which is exactly the failure this lab teaches you to check for first.

Campus design decisions

Access: endpoints and VLAN membership. Distribution: aggregation, routing boundary, policy. Core: efficient resilient backbone. A switch block is access plus distribution.

Use two upstream devices and redundant links; know which links are Layer 2 and Layer 3. Keep VLANs within the intended block. Routed access moves the routing boundary downward; a collapsed core combines distribution/core roles. Size by traffic and failure conditions, not only user count.

Wireless architecture and roaming

IBSS: ad hoc. BSS: AP plus clients. ESS: connected BSSs. SSID: network name. A PHY rate is not actual throughput.

Split-MAC: LAP handles real-time radio work; WLC handles central management. CAPWAP control is protected; data-tunnel encryption is optional in the deck. Centrally switched traffic passes through the WLC.

Intracontroller: same WLC, new AP tunnel. Layer 2 intercontroller: new WLC, same subnet. Layer 3 intercontroller: new local subnet, anchor/foreign tunnel preserves the original client IP. CCKM, PKC/OKC, and 802.11r reduce repeated authentication work with compatible support.
